# Build Dense Tabular Layout from Content Extremes and Rule Hierarchy

## Pattern Rule
**IF** a publication must present dense tables or repeated numeric information inside a constrained text area
**THEN** derive column divisions from representative longest entries and comfortable spacing, then use selective rules, fields, and typographic distinctions to separate rows, sections, and support information without making the table denser than its content requires
**ELSE** use the ordinary page grid and typographic hierarchy when the information does not need a dedicated tabular structure.

## Do
- Test the table with real content, including the longest ordinary figures or labels, before fixing column divisions.
- Divide the available manuscript or grid width according to what the entries actually require rather than giving every column an equal share by default.
- Preserve comfortable spacing between neighboring figures or information groups so density does not erase scanability.
- Use dashed or solid rules, changes in rule weight or tonality, or bounded fields selectively when they help readers distinguish rows, major sections, and subsections.
- Coordinate table headers, captions, diagram text, and supporting labels with the publication's broader typographic hierarchy so the table belongs to the same system even when its internal structure is more exacting than ordinary prose.
- When dense information forces smaller text, test whether leading and surrounding space keep extended reading comfortable enough for the publication's purpose.

## Don't
- Do not size columns from placeholder averages when an ordinary long figure or label will break the structure.
- Do not divide columns uniformly merely because the page grid is uniform if the table entries need materially different widths.
- Do not add every possible rule or box; excessive separators can compete with the data instead of clarifying it.
- Do not treat tabular typography as a separate visual language that abandons the hierarchy and character established elsewhere in the publication.
- Do not solve an over-dense table only by reducing type size when spacing, column allocation, or section structure can carry part of the load.

## Checklist
- Representative longest figures or labels fit without forcing ad hoc column changes.
- Column widths reflect the content they carry and preserve usable spacing between information groups.
- Rules, fields, or tonal separators distinguish meaningful row and section relationships without overwhelming the entries.
- Headers, captions, and supporting labels remain clearly subordinate or distinct according to their actual information roles.
- The table still reads as part of the publication's larger typographic system.
- Any reduction in text size has been tested with sufficient leading and surrounding space for the intended reading duration.

## Notes
Dense tabular material is not ordinary prose poured into a grid. Its geometry should respond to the entries it must hold. Start from the longest representative figures and the spacing needed to keep neighboring information distinct, then let column divisions vary inside the available manuscript width. Rules and tonal fields can clarify major and minor groupings, but they work best as hierarchy rather than decoration. The surrounding publication system still matters: table headers, captions, diagrams, and supporting text should remain recognizably related to the publication even when the data section needs tighter, more precise internal organization.
