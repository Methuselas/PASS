# Build Publication Color System for Semantic Distinction and Navigation

## Pattern Rule
**IF** a publication uses color repeatedly to distinguish sections, information roles, document families, or levels of emphasis
**THEN** assign a small, coherent set of color relationships to explicit semantic jobs, keep those assignments consistent enough to be learned, and verify the distinctions in their actual page context so color clarifies rather than adds another code the reader must decipher
**ELSE** use color expressively without pretending it forms a navigation or information system.

## Do
- Decide what color is supposed to distinguish before choosing the palette: sections, recurring text roles, product families, document classes, levels of promotional versus informational emphasis, or another named relationship.
- Build the color system from the publication's concept, audience, and existing visual content rather than applying a generic palette after the structure is already finished.
- Keep the coding set simple enough that readers can recognize the categories without continually consulting a key.
- Make category differences perceptible in context. Judge neighboring colors at their actual size, value, saturation, and surrounding field rather than from isolated swatches.
- Allow a stable base palette with changing accents when continuity across the publication matters but sections or editions still need distinction.
- Use the amount, placement, or intensity of a family color consistently when those variables are carrying meaning, not merely the hue itself.
- Compare candidate color assignments against the words, images, and page structures they will accompany; recoloring an element can change its apparent meaning, emphasis, and spatial relationship.
- Treat color-wheel relationships such as analogous, complementary, or triadic groupings as possible organizing aids, not as automatic semantic systems.
- Recheck the system after several pages or components are assembled. A code that works on one spread may become noisy, ambiguous, or overly complex when repeated through the full publication.

## Don't
- Do not assign a unique color to every category simply because the palette can support it; too many codes create a memory burden and weaken recognition.
- Do not assume color names or symbolic meanings are universal. Cultural and individual interpretation can alter the message even when perception of the color difference itself is clear.
- Do not use two coding colors whose differences collapse at the actual scale, value, or surrounding context of the publication.
- Do not let a color code contradict stronger hierarchy cues in typography, placement, or sequence.
- Do not change an established category color casually from page to page; if the semantic assignment changes, make that change intentional and system-wide.
- Do not confuse an expressive palette with an information code. Color may contribute mood or positioning without needing to label categories.

## Checklist
- Every recurring coding color has a named information or navigation job.
- The number of color categories remains learnable across the whole publication.
- Adjacent or related coding colors are visibly distinct in their real page context.
- Stable colors and changing accents follow a deliberate relationship rather than drifting between pages or editions.
- Color assignments reinforce the publication's content organization and do not conflict with stronger typographic or spatial hierarchy.
- The system still reads after several representative pages, sections, or related documents are viewed together.
- Any culture-dependent meaning is treated as audience-specific rather than as an inherent property of the hue.

## Notes
Color in a publication can operate as content as well as appearance. Samara distinguishes its expressive and associative roles from its systematic role: color can identify recurring kinds of information, connect related components or editions, and help readers recognize section changes. That only works when the coding remains simple, perceptible, and consistent. The same color also changes with context—surrounding value, saturation, area, and neighboring hues can alter how it appears—so a publication color system must be tested in the composed pages rather than approved as isolated swatches. Use the general color-strategy owner for palette character and audience-sensitive associations; use this Pattern when repeated color assignments must carry a stable information or navigation function across a multipage system.
