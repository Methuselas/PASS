# Proof a Designed Publication in Output Form Before Release

## Pattern Rule
**IF** a publication has entered designed or typeset output and is approaching release
**THEN** inspect a proof that reproduces the intended output closely enough to expose layout, typesetting, cover, and production defects, correct what it reveals, and proof again until the release is stable
**ELSE** continue manuscript and layout development without treating an unfinished working view as final proof.

## Do
- Read the typeset pages again even when the manuscript was already edited; layout can expose new spacing, line-break, pagination, and text errors that were invisible earlier.
- Check the cover and interior at their intended physical or faithful output size rather than relying only on enlarged working views.
- Use successive proof rounds deliberately: early rounds can concentrate on text and page-system defects while later rounds verify the corrected cover, typography, and production result.
- When a printer supplies separate color and content proofs, use them for their different jobs: judge color reproduction on the color proof and use the content proof to check text, crossovers, page sequence, image sharpness, and whether fonts or text flow shifted during prepress.
- Write corrections directly and unambiguously on the agreed proof or markup medium, return them promptly, and request another proof when a significant change could alter layout or output.
- Attend or request a press check when the production route makes on-press color approval materially useful, and approve the actual adjusted sheet rather than relying only on the earlier simulation.
- Make corrections between proofs and inspect the changed output again instead of assuming the fix propagated cleanly.
- Delay release approval until the proof itself, not merely the source files, survives the final review.

## Don't
- Do not assume manuscript editing eliminates the need to inspect the typeset publication.
- Do not treat one proof as sufficient merely because the first round found only a few defects.
- Do not rush the last proof because production or publication has already been scheduled.
- Do not approve final output from a view that cannot reveal the physical-scale or reproduction problems the intended medium may introduce.
- Do not use a color simulation as the only check for page order, text reflow, font substitution, or image sharpness when a content proof exposes those failures more directly.
- Do not make substantial corrections only in printer-side markup when they belong in the designer's source layout; update the source and reproof the changed pages.

## Checklist
- The latest proof reflects all intended corrections.
- Typeset text has been reread in its designed context.
- Cover, recurring page elements, margins, pagination, and image placement have been checked at output scale.
- Printer proofs have been checked for color, image sharpness, text reflow, font integrity, crossovers, and page sequence according to the proof type provided.
- No correction introduced a new layout or continuity defect elsewhere.
- Release approval follows a reviewed proof rather than an unverified source file.

## Notes
Editing and design create different classes of error. A manuscript can be clean before layout and still acquire awkward breaks, misplaced elements, or new visible mistakes after typesetting. Repeated output proofs turn the final publication into the thing being reviewed, which is especially important once corrections become costly after release. In commercial printing, different proofs can expose different failure classes, and significant changes should return to the source layout and generate another proof rather than existing only as production-side corrections.
