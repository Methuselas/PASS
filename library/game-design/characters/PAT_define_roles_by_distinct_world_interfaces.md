# Define Roles by Distinct World Interfaces

## Pattern Rule
**IF** character roles are supposed to create genuinely different professional identities
**THEN** give each role a distinct interface with world state—different verbs, access, legitimacy, resources, information, scale, or specialist authority—and build representative situations in which those interfaces can materially alter outcomes
**ELSE** treat the distinction as a skill emphasis or character concept rather than advertising it as a separate role architecture.

## Do
- State each role's privileged question or verb: who can command institutional resources, mobilize crowds, call on a community, control a technical environment, invoke legal authority, acquire restricted goods, or otherwise change the solution space.
- Give the setting enough institutions, markets, crowds, networks, legal structures, technical systems, or relationships for the advertised role interfaces to exist naturally.
- Allow adjacent roles to attack the same problem through different methods, costs, risks, or scopes instead of making one role the mandatory key.
- Distinguish numerical privilege from agency privilege. A role may be distinctive because it acts more reliably on common verbs or because it can attempt verbs others cannot.
- Audit **interface breadth**, not only interface uniqueness. A role framed as owning one fictional domain can still become a generalist if that domain supplies reliable solutions to combat, reconnaissance, healing, mobility, stealth, social control, information, defense, and other roles' recurring problems. Price and constrain the breadth of consequential problem classes the interface can alter, not merely the number of named powers it contains.

## Don't
- Assume a flavorful profession produces different play if the character proposes the same solutions as everyone else.

## Checklist
- Each role has at least one named world interface and a recurring reason to use it.
- Representative adventures expose those interfaces without requiring contrived token scenes.
- At least one shared problem admits more than one legitimate professional approach.
- Removing a role changes the team's available methods without making the campaign structurally unplayable.
- A broad specialist interface has been tested against the recurring problem domains claimed by adjacent roles; no single role routinely owns several other roles' highest-value verbs without corresponding scarcity, risk, preparation, or opportunity cost.

## Notes
Strong role identity is often a relationship between the character and the world rather than a bundle of internal bonuses. A combat specialist may gain numerical privilege, while a fixer-like character gains access, a corporate operator gains institutional leverage, or a network specialist gains exclusive control verbs. Distinctive fiction does not by itself protect niches: one privileged interface can still be mechanically overbroad when it reliably reaches many independent problem classes. Role design should therefore count the breadth of consequential verbs and scenario domains the interface can replace or transform, not only whether the interface has a unique name. Balancing the value of those interfaces and keeping deep specialist procedures participatory are adjacent decisions with separate owners.
