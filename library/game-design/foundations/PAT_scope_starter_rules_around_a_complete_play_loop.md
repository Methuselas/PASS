# Scope Starter Rules Around a Complete Play Loop

## Pattern Rule
**IF** the full game asks newcomers to absorb more progression, campaign scale, or rules surface than they need to begin meaningful play
**THEN** define a bounded starter scope that contains everything needed to complete and repeat its promised play loop, while stating what is deferred and how users continue into the wider game
**ELSE** teach the full game directly when separating a starter scope would create an artificial product or procedure boundary.

## Do
- Choose the smallest recurring loop that expresses the game's real identity rather than a disconnected tutorial exercise.
- Include every rule, role, opposition procedure, reward, recovery step, and referee responsibility needed to repeat that loop without hidden designer knowledge.
- Set a visible boundary on progression, geography, subsystem access, or campaign scale so learners know what the starter material does and does not promise.
- Preview later possibilities when that creates useful motivation without requiring the learner to operate those rules yet.
- Give a clear continuation path so the next stage feels like expansion of a known game rather than an unexplained replacement.

## Don't
- Call a document beginner-friendly when it omits a common-path dependency needed to finish its advertised loop.
- Include advanced procedures simply because they exist elsewhere in the full game.
- Hide a hard progression or scope boundary until the learner reaches it.
- Teach a fake simplified game whose operating assumptions must be unlearned before normal play can begin.

## Checklist
- A newcomer can complete and repeat the advertised loop using only the declared starter material.
- Deferred rules are not required by any common-path procedure inside the starter scope.
- The stopping boundary is explicit before users invest past it.
- The continuation path identifies what expands next without redefining the rules already learned unnecessarily.
- At least one advanced possibility can remain visible without becoming an onboarding dependency.

## Notes
A starter game is a scope decision, not merely a shorter rulebook. Good compression removes responsibilities that do not yet need to be operated while preserving a complete piece of the real game. This creates an honest entry surface: learners can play something whole, understand where its boundary lies, and expand later without discovering that the initial experience was only a disposable simulation of the actual system.
