# Keep Semantic Difficulty Labels Mechanically Consistent

## Pattern Rule
**IF** the game uses semantic difficulty categories such as Easy, Hard, Very Hard, or equivalent labels across multiple tasks or domains
**THEN** keep each label's mechanical translation stable within the shared resolution grammar while allowing the facilitator to judge which label the fiction warrants
**ELSE** use direct mechanical inputs rather than adding labels whose meaning drifts from one subsystem to another.

## Do
- Define the mechanical effect of each difficulty label once for the resolution grammar that uses it.
- Let the facilitator or procedure judge the fictional category when open-ended adjudication is useful, while keeping the category's mechanical consequence stable.
- Use the same label for comparable mechanical pressure across skills and domains that share the grammar.
- Add a distinct label or explicit exception only when the game needs a genuinely different mechanical state rather than a new adjective for the same one.
- Test examples from several domains to verify that equivalent labels produce equivalent mechanical changes.
- Keep impossible or no-roll boundaries explicit when a label would otherwise imply that every fictional task can be attempted through the same progression.

## Don't
- Let "Hard" mean one modifier in one skill and a different unannounced modifier in another subsystem that claims to share the same grammar.
- Multiply synonymous labels whose only purpose is tone rather than a distinct mechanical translation.
- Use a semantic category to hide facilitator fiat about the actual mechanical effect.
- Treat stable mechanical translation as a requirement that every facilitator must judge the fictional category identically.

## Checklist
- Each semantic difficulty label has one stated mechanical translation within its grammar.
- Equivalent labels behave consistently across the tasks that claim to share that grammar.
- Fictional judgment and mechanical translation are distinguishable responsibilities.
- Any exception or additional category corresponds to a real mechanical distinction.
- Examples from more than one domain confirm that label meaning does not drift.
- The grammar still distinguishes tasks that should not invoke resolution at all.

## Notes
Semantic labels can provide a useful interface between open-ended fiction and fixed mechanics. The facilitator may decide that one situation is Hard and another Easy without needing a rule for every possible circumstance, but players can still learn what those categories mean mechanically. Flexibility belongs in choosing the label; consistency belongs in resolving it.
