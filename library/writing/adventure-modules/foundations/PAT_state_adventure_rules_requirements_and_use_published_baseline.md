# State Adventure Rules Requirements and Use the Published Baseline

## Pattern Rule
**IF** an adventure is written for operators beyond the author's own table and depends on a particular ruleset, capability range, supplement, or rules interpretation
**THEN** state those prerequisites up front and express the scenario through the ordinary published rules rather than unannounced house interpretations
**ELSE** omit rules boilerplate that does not change what the operator must prepare or understand

## Do
- State the intended system or edition and any character level, skill, class, or comparable capability requirements that materially affect whether the scenario can be run as written.
- Name additional rulebooks or supplements when the operator must consult them for creatures, procedures, abilities, or other required content.
- Prefer the simplest standard interpretation that communicates the situation adequately when a private table ruling would create avoidable ambiguity for outside readers.
- Check mechanical references for semantic mistakes that ordinary spelling or grammar tools cannot catch, such as naming the wrong ability, condition, or procedure.
- Leave campaign-specific house interpretations to the receiving table when the published baseline already supports the scenario.

## Don't
- Present a private house rule as though every reader shares it.
- Hide a required supplement or assumed character capability until the encounter that needs it.
- Complicate the written procedure merely to preserve a table-specific interpretation that an outside operator does not need.
- Assume that syntactically correct rules text is operationally correct when a wrong statistic, ability, or condition would change play.
- Rely on a remembered table convention when the stated rulebook already provides the procedure an outside operator is expected to recognize.

## Checklist
- The operator can identify the ruleset, required supplements, and material capability assumptions before preparing the adventure.
- No required encounter depends on an unstated private ruling.
- Rules references use terminology and procedures recognizable from the stated published baseline.
- Mechanical names and calls have been checked for meaning, not only spelling and grammar.
- Removing any listed prerequisite would make at least one part of the adventure materially harder or impossible to run as written.

## Notes
An adventure written only for its author can lean on table habit and remembered rulings. A published or shared module cannot. Stating the actual rules requirements and staying close to the common baseline reduces the amount of translation another operator must perform before play. This is a manuscript-compatibility decision: receiving tables can still modify the scenario for their own campaigns, but the shared manuscript itself stays on the published baseline rather than requiring the author's private table conventions.
