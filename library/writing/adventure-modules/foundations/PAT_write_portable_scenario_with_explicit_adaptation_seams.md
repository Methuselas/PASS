# Write a Portable Scenario with Explicit Adaptation Seams

## Pattern Rule
**IF** an adventure is meant to be inserted into more than one campaign, region, or host setting
**THEN** separate the scenario elements that must remain stable from the local details that should be adapted, state the minimum placement requirements, and tell the operator which surface details to replace so the inserted adventure feels native to its host setting
**ELSE** write directly for the fixed setting when portability would only dilute specific social, geographic, or historical relationships

## Do
- Identify the scenario's invariants: the conflict, necessary actors, required locations or functions, hidden causal relationships, and any scale or travel assumptions that cannot change without rewriting the adventure.
- State the minimum host conditions the scenario needs, such as a small settlement, an isolated route, a local authority, nearby wilderness, a particular social institution, or enough distance for help to be unreliable.
- Mark adaptable surfaces such as local names, architecture, clothing, weather, nearby political affiliations, religious forms, landscape details, and ordinary services.
- Offer multiple entry hooks when the same invariant conflict can plausibly connect to different campaign obligations, patrons, missing persons, local problems, or practical needs; keep those hooks replaceable without rewriting the scenario core.
- Tell the operator to read the surrounding host-setting material before adapting those surfaces so the inserted locale inherits recognizable regional particulars rather than generic decoration.
- Preserve local causal logic after relocation: if a community's isolation, authority, economy, custom, or environment matters to the scenario, adapt those functions rather than merely renaming them.
- Keep the adaptation burden bounded by giving a small set of integration targets instead of asking the operator to rewrite the whole module.
- Recheck every clue, route, relationship, and consequence after relocation for assumptions that depended on the original placement.

## Don't
- Claim a scenario can go "anywhere" while leaving unspoken requirements that only one kind of place can satisfy.
- Tie a portable scenario to one narrow entry motive when alternate hooks could connect the same core situation to different campaigns without changing its downstream logic.
- Make portability by stripping away all specific texture until the location feels interchangeable and empty.
- Preserve names or decorative motifs while ignoring host-setting institutions, geography, travel logic, or social expectations that would make the scenario behave differently.
- Require the operator to absorb an entire setting line before identifying the few local details that actually need adaptation.
- Treat a fixed, deeply place-dependent story as a portable insert when relocation would break its motives, history, or consequences.

## Checklist
- The scenario's invariant core can be named separately from its adaptable surface details.
- The operator can state the minimum conditions a host setting must supply before inserting the scenario.
- The module names a bounded set of local details that should be adapted for consistency.
- When several hooks are supplied, each can reach the same invariant scenario state without changing the conflict, required locations, or later causal logic.
- Host-setting research changes concrete details rather than merely adding cosmetic names.
- Relocation does not break required routes, clues, social authority, motives, or consequences.
- The adapted scenario still feels specific to its new location rather than generically portable.

## Notes
Portable adventure writing works best when the author provides seams rather than vagueness. Entry hooks can be part of those seams: several different obligations or local problems may legitimately point into the same stable conflict, letting the operator choose the connection that fits the host campaign without rewriting what happens after involvement begins. A village, station, neighborhood, ruin, or roadside crisis may be relocatable because its dramatic functions are compact, but the inserted version still needs to inherit the host setting's visible and social texture. The writer therefore preserves the load-bearing relationships while deliberately exposing a few surfaces for replacement.

The practical test is not whether the original map name can be changed. It is whether the operator can move the scenario without having to rediscover which assumptions were essential, and whether the relocated version reads as if it belongs where it was placed.
